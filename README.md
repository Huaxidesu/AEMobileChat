# GTNHChat

面向 Minecraft 1.7.10（GTNH / Thermos）服务端的聊天格式化与跨服转发模组。

把玩家聊天渲染成带悬停提示和点击动作的富文本，并在同一代理网络内的多台服务器之间互相转发。
服务端装一个 jar 即可，**代理端不需要装任何东西**。

## 特性

- 按权限和 op 等级匹配聊天规则，规则顺序就是配置里的书写顺序
- 不同身份可用不同样式，例如管理员的名字显示为红色
- 格式片段支持颜色码、多行悬停、点击执行命令 / 补全 / 打开链接
- 跨服聊天走代理内置的 `Forward` 子通道，转发原始数据、各服按自己的样式渲染
- 任务分享（任务书）跨服后仍可点击
- NEI 物品链接连物品数据一起转发，别的服也能点开
- 成就公告：客户端检测解锁并上报，服务端统一公告并转发
- 无任何联网行为：不检查更新、不上报数据、不加载远程配置

## 环境要求

| 项 | 版本 |
|---|---|
| 服务端 | Minecraft 1.7.10 + Thermos / Cauldron 类实现 |
| Java | 8 |
| 代理（可选） | BungeeCord 或其 1.7 兼容分支 |
| 客户端 | 可选，装了才有成就公告 |
| 软依赖 | NEI（物品链接桥）、BetterQuesting（任务分享） |

## 下载

打包好的 jar 挂在 [Releases](../../releases) 里：推一个 tag 时由 GitHub Actions 构建并附上产物，
`gtnchat-1.7.10-<版本>.jar` 就是放进服务端 `mods/` 的那一个。想自己编也行，见上。

## 构建

```bash
git clone <repo>
cd GTNHChat
./gradlew build
```

产物在 `build/libs/`。仓库里没有二进制文件，依赖由 Gradle 自行解析。

## 使用

1. 把 jar 放进服务端 `mods/`
2. 启动一次，生成 `config/gtnchat/config.yml` 与 `style.yml`
3. 按需修改，`/gtchat reload` 生效
4. 多台服务器共用聊天时，给每台设置不同的 `server.id`

配置说明见文档。
